# CS 320: Software Testing, Automation, and Quality Assurance

## Course Portfolio

This repository contains my portfolio artifacts from CS 320 at Southern New Hampshire University. The projects demonstrate my experience developing Java applications, implementing JUnit tests, evaluating software requirements, and applying software testing techniques to improve reliability and quality.

## How can I ensure that my code, program, or software is functional and secure?

I ensure that my software is functional and secure by understanding the requirements, validating user inputs, and developing unit tests to identify potential defects. During Project One, I used JUnit testing to evaluate the Contact Service application, including its ability to add, update, and delete contacts while enforcing specific data requirements. Testing both valid and invalid inputs helped me understand the importance of identifying problems before software is released.

I also learned that passing unit tests does not automatically guarantee that software is secure. Secure development requires careful input validation, appropriate access controls, code reviews, and additional security testing. These practices help reduce vulnerabilities while improving the reliability of the application.

## How do I interpret user needs and incorporate them into a program?

I begin by reviewing the user's requirements and identifying what the software must accomplish. I then translate those requirements into specific functions, validation rules, and test cases. For the Contact Service project, this involved understanding restrictions on contact IDs, names, phone numbers, and addresses and ensuring that the application handled those requirements correctly.

My background in engineering and troubleshooting has taught me that understanding the problem is just as important as implementing the solution. I apply that same principle to software development by breaking requirements into manageable tasks and verifying that the completed program meets its intended purpose.

## How do I approach designing software?

My approach to designing software starts with identifying the problem, understanding the requirements, and organizing the solution into smaller components. I focus on writing code that is readable, maintainable, and easy to test.

During CS 320, separating the Contact class from the ContactService class helped me understand how individual components can be developed and tested independently. Using JUnit also reinforced the value of automated testing when making changes or identifying unexpected behavior.

As I continue pursuing my computer science degree and preparing for a career in software and systems engineering, I plan to apply these lessons to develop reliable, secure, and maintainable applications.
